# Очистка Redux state при выходе

## Цель и границы

При выходе возвращать весь Redux state приложения в начальное состояние. Помимо параметров сессии должны удаляться добавленные чаты, активный чат, загруженная история и связанные статусы. Логику входа и запросов не менять.

## Наблюдаемое и ожидаемое поведение

Сейчас `clearCredentials` очищает только session slice. Chats slice остаётся в памяти, поэтому при новом входе в той же вкладке может отобразиться состояние предыдущей сессии.

После изменения действие `clearCredentials` сбрасывает корневой state. Session и chats повторно инициализируются начальными значениями. Подписка store замечает очищенную сессию и выполняет предусмотренную текущей задачей `0011` очистку `localStorage`.

## Текущая реализация

- [`sessionSlice`](../../src/entities/session/model/sessionSlice.ts) содержит действие `clearCredentials`.
- [`chatSlice`](../../src/entities/chat/model/chatSlice.ts) хранит чаты, сообщения и активный чат только в Redux.
- [`store`](../../src/app/store/index.ts) сейчас передаёт объект slice reducers непосредственно в `configureStore`.

## Решение

Собрать slice reducers через `combineReducers` и добавить app-level reducer-обёртку. При совпадении action с `clearCredentials` передать корневому reducer `undefined`, чтобы Redux Toolkit создал начальное состояние всех slices. Такое решение находится в слое `app` и не создаёт запрещённой зависимости между entities одного слоя.

## Этапы и затрагиваемые файлы

1. Добавить корневой reset в `src/app/store/index.ts`.
2. Выполнить автоматические проверки.
3. Оформить результат в `status.md` и `implementation.md`.

## Приватность и безопасность

Сброс предотвращает сохранение чатов и сообщений предыдущей авторизации в памяти вкладки после выхода. Данные не логируются и не передаются дополнительно.

## Риски и критерии приёмки

После выхода session содержит пустые поля, chats является пустым объектом, активный чат и история отсутствуют. При обычных actions store работает без изменений. Восстановленная из `localStorage` валидная сессия продолжает применяться при создании store.
