# Отправка сообщений

## Цель и границы

Реализовать отправку текстовых сообщений из формы активного чата через API с параметрами текущей сессии.

В задачу входит отправка непустого текста, обработка состояний запроса и согласованное обновление истории активного чата. Отправка файлов, изображений, аудио, видео, контактов, геолокации, реакций и других нетекстовых данных не входит в границы задачи.

## Наблюдаемое и ожидаемое поведение

Сейчас форма активного чата выводит введённый текст в консоль и очищает поле. После реализации `Enter` или кнопка отправки должны выполнять API-запрос, отражать результат в интерфейсе и не терять текст при неуспешной отправке.

## Текущая реализация

- `src/widgets/chat-details/ui/ChatDetails.tsx` — форма сообщения и временная обработка отправки.
- `src/entities/chat` — состояние чатов и загруженных текстовых сообщений.
- `src/features/chat-history` — получение и фильтрация истории активного чата.
- `src/entities/session` — параметры подключения к API.
- `src/shared/api` — общий HTTP-транспорт.

## Решение

- Отправлять непустой текст методом `POST /waInstance{idInstance}/sendMessage/{apiTokenInstance}` с `chatId` и `message` в JSON-теле.
- Считать отправку успешной при успешном HTTP-ответе с непустым строковым `idMessage`.
- После успешной отправки запрашивать сообщение методом `POST /waInstance{idInstance}/getMessage/{apiTokenInstance}` с `chatId` и полученным `idMessage`.
- Преобразовывать результат `GetMessage` тем же обработчиком текстовых сообщений, который используется для истории, и добавлять его в `messages` нужного чата.
- Блокировать повторную отправку того же сообщения во время запроса.
- Очищать поле после получения `idMessage`, до запроса записи журнала.
- При ошибке `SendMessage` сохранять текст и показывать тултип «Ошибка отправки сообщения, попробуйте позже».
- Для ошибок отправки и поиска номера использовать тултип со стрелкой, который автоматически скрывается через 5 секунд.
- Ограничить ввод 4000 символами согласно контракту API.
- Показывать понятное состояние ошибки без вывода текста сообщения, токена или полного URL в логи.

## Согласованный контракт

- Сообщение добавляется в состояние только по результату `GetMessage`, без оптимистичной записи.
- Ошибка `GetMessage` после успешного `SendMessage` не считается ошибкой отправки: поле остаётся очищенным, сообщение в состояние не добавляется.
- Пустой или состоящий только из пробелов текст не отправляется.
- Статус доставки отдельно не обновляется.

## Этапы и затрагиваемые области

1. Уточнить контракт API и критерии успешной отправки.
2. Спроектировать состояние отправки сообщения.
3. Реализовать запрос отправки текстового сообщения.
4. Подключить запрос к форме активного чата.
5. Обновить историю и состояния интерфейса после результата запроса.
6. Выполнить релевантные автоматические проверки.

## Приватность и безопасность

Текст сообщения относится к пользовательским данным. Его нельзя выводить в консоль после подключения реальной отправки, сохранять вне состояния чата или включать в документацию и тестовые fixtures. Параметры сессии и URL с токеном не должны попадать в логи и пользовательские сообщения об ошибках.

## Риски и ограничения

- Повторный submit не должен создавать дубликаты сообщений.
- Ответ API может не содержать всех полей, необходимых текущей модели истории.
- Запись отправленного сообщения может быть доступна в журнале не сразу; автоматического повтора `GetMessage` нет.
- Ошибка сети не должна очищать введённый текст.
- Переключение активного чата во время запроса не должно добавлять сообщение в другой чат.

## Критерии приёмки

- Непустой текст отправляется в выбранный чат по согласованному API-контракту.
- `Enter` и кнопка submit запускают один и тот же сценарий отправки.
- Повторная отправка блокируется на время запроса.
- При успехе поле очищается, а сообщение появляется в истории нужного чата.
- При ошибке отправки текст сохраняется, а тултип со стрелкой и заданным текстом автоматически скрывается через 5 секунд.
- В консоль и документацию не попадают текст сообщения и чувствительные параметры сессии.
- Нетекстовые сообщения не отправляются и не сохраняются.
