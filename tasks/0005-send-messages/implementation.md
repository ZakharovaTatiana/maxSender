# Реализация отправки сообщений

## Поведение

Форма активного чата отправляет непустой текст через `SendMessage`. На время запроса повторный submit блокируется. Успешным считается HTTP-ответ с непустым строковым `idMessage`; после него поле ввода очищается и выполняется запрос `GetMessage` для того же чата.

Полученная запись проходит общий разбор текстовых сообщений, используемый историей чата, и добавляется в `messages` соответствующего чата. Дубликат с тем же `idMessage` не добавляется, а итоговый список сортируется по времени по возрастанию.

При ошибке `SendMessage` введённый текст сохраняется. Над полем появляется тултип «Ошибка отправки сообщения, попробуйте позже» со стрелкой вниз, который автоматически скрывается через 5 секунд. Такой же вид и время показа применены к ошибке поиска номера.

## Состояние и зависимости

Параметры API берутся из текущей сессии. В Redux добавлено действие для одного сообщения; локальное состояние формы хранит текст, ошибку и признак выполняющейся отправки. Новые зависимости не добавлялись.

## Ограничения

- Отправляются и сохраняются только текстовые сообщения.
- Длина ввода ограничена 4000 символами.
- После успешного `SendMessage` неуспешный `GetMessage` не восстанавливает текст и не показывает ошибку отправки, поскольку API уже принял сообщение.
- Автоматического повтора `GetMessage` и обновления статуса доставки нет.
