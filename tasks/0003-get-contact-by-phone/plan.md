# Получение контакта по номеру телефона

## Цель и границы

Добавить получение данных контакта по номеру телефона для авторизованного пользователя через API с текущими параметрами сессии, сохранить найденные чаты в состоянии приложения и вывести их в панели «Чаты».

Отправка сообщений, загрузка истории переписки и получение сведений о контакте, кроме `chatId`, в эту задачу не входят.

## Наблюдаемое и ожидаемое поведение

Поле поиска отправляет запрос проверки номера. После расширения задачи успешный ответ должен добавлять чат в список под формой, а любой неуспешный результат — показывать сообщение над полем.

## Текущая реализация

- `src/widgets/chat-panel/ui/ChatPanel.tsx` — панель с полем поиска по номеру телефона.
- `src/entities/session/model/sessionSlice.ts` — параметры подключения `idInstance`, `apiTokenInstance` и `apiUrl`.
- `src/app/store/index.ts` — Redux store приложения.

## Решение

- Вынести общий обработчик HTTP-запросов в `shared/api`.
- Реализовать запрос проверки номера в feature поиска контакта.
- Добавить перед номером селектор только с кодами `+7` и `+375`, без подписей стран; по умолчанию выбирать `+7`.
- Принимать в поле национальную часть номера: 10 цифр для РФ и 9 цифр для РБ.
- При вставке полного номера с кодом страны и необязательным знаком `+` удалять код из поля; для кода `375` автоматически выбирать РБ.
- Отправлять `POST` на `{{apiUrl}}/waInstance{{idInstance}}/checkAccount/{{apiTokenInstance}}` с введённым номером в теле запроса.
- Оформить существующий инпут как форму и показывать кнопку submit в конце поля только при непустом вводе.
- Считать успешным только HTTP-ответ с валидным JSON, `exist: true` и числовым `chatId`.
- Хранить чаты в Redux как объект с ключами `chatId`; новой записи назначать `order`, равный максимальному существующему значению плюс один.
- После первого добавления чата один раз запрашивать `GetContactInfo`; при успешном ответе сохранять все полученные поля в свойстве чата `contactInfo`.
- Выводить чаты под формой по `order` с именем и круглым аватаром.
- При наличии `contactInfo` выбирать имя чата в порядке `name`, `contactName`, ненулевой `phoneNumber`, `chatId`, пропуская отсутствующие и пустые значения.
- Для аватара использовать непустую ссылку `contactInfo.avatar`; без неё показывать на цветном фоне первый символ имени либо первые символы первых двух слов составного имени.
- При ошибке показывать над полем сообщение «ошибка номера, либо пользователь с таким номером не найден» на красноватом фоне.
- Не выводить параметры подключения и токен в интерфейс, логи или сообщения об ошибках.

## Приватность и безопасность

Номер телефона относится к персональным данным и не должен сохраняться без отдельного требования, попадать в логи или документацию задачи. `apiTokenInstance` должен использоваться только для обращения к API и не должен включаться в пользовательские сообщения об ошибках.

## Риски и ограничения

- При ручном вводе поле принимает только цифры национальной части номера.
- Вставляемое значение с символами, кроме необязательного начального `+` и цифр, отклоняется.
- Повторный поиск уже добавленного `chatId` не создаёт дубликат и сохраняет его исходный `order`.
- Ошибка `GetContactInfo` не отменяет добавление чата; автоматический повторный запрос в рамках задачи не выполняется.
- Данные сессии входят в URL согласно контракту внешнего API, поэтому URL запроса нельзя логировать.

## Критерии приёмки

- Поле поиска находится внутри формы.
- При пустом вводе кнопка поиска скрыта и форма не отправляется.
- При непустом вводе в конце поля отображается кнопка поиска; до прохождения валидации она отключена.
- Для РФ форма валидна при 10 цифрах в поле, для РБ — при 9 цифрах.
- При отправке выбранный код добавляется к номеру без знака `+`.
- При вставке полного номера код страны удаляется из поля, а код `375` переключает селектор на РБ.
- Отправка формы выполняет POST-запрос по адресу из параметров текущей сессии.
- Тело запроса содержит введённый номер телефона.
- Ответ без `exist: true` или числового `chatId`, ошибка сети, неуспешный HTTP-статус и невалидный JSON отображаются как единая ошибка поиска.
- Успешный ответ добавляет чат в Redux-состояние с очередным `order`.
- Для впервые добавленного чата выполняется один запрос `GetContactInfo`, а успешный ответ сохраняется в `contactInfo`.
- Список чатов отображается под формой по возрастанию `order`.
- Имя чата выбирается по цепочке `name` → `contactName` → ненулевой `phoneNumber` → `chatId`.
- Аватар отображается по ссылке из `contactInfo.avatar`, а при её отсутствии заменяется инициалами выбранного имени.
- Чувствительные параметры сессии и номер телефона не попадают в логи.
