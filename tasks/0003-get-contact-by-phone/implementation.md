# Реализация

## Итоговое поведение

Поле «Найти по номеру телефона» оформлено как форма. Пока значение пустое, кнопка поиска скрыта. После ввода непустого значения справа появляется кнопка submit, которая остаётся отключённой до прохождения валидации.

Перед полем номера расположен селектор только с кодами `+7` / `+375`, без текстовых пояснений; по умолчанию выбран `+7`. Поле принимает 10 цифр для РФ или 9 цифр для РБ. При отправке код выбранной страны добавляется к номеру без знака `+`, после чего выполняется POST-запрос по адресу `{{apiUrl}}/waInstance{{idInstance}}/checkAccount/{{apiTokenInstance}}`.

При вставке полного номера с кодом `7` или `375`, в том числе со знаком `+`, код удаляется из поля. Распознанный код `375` автоматически переключает селектор на РБ. Невалидное содержимое буфера не вставляется.

Ответ считается успешным при успешном HTTP-статусе, валидном JSON, `exist: true` и числовом `chatId`. Такой чат добавляется в Redux-состояние и выводится под формой. Для нового чата `order` равен максимальному существующему значению плюс один; повторный поиск не создаёт дубликат. Любой неуспешный результат показывает над полем единое сообщение на красноватом фоне.

Сразу после первого добавления чата выполняется один запрос информации о контакте. Успешный ответ целиком сохраняется в `contactInfo`. Имя в списке выбирается по первому доступному значению: непустой `name`, непустой `contactName`, ненулевой `phoneNumber`, затем `chatId`. Непустая ссылка `avatar` отображается как круглая фотография; без неё на цветном круге показывается первый символ имени или первые символы первых двух слов. Ошибка дополнительного запроса не удаляет уже добавленный чат и не приводит к автоматическому повтору.

## Ключевые изменения

- В `shared/api` добавлен единый stateless-обработчик HTTP-запросов.
- В feature `contact-search` размещены конкретный запрос `checkAccount` и форма поиска.
- В feature `contact-search` добавлены правила стран, проверка национальной части и разбор номера из буфера обмена.
- В entity `chat` добавлены состояние, добавление без дублей и представление списка чатов.
- В feature поиска добавлены запрос информации о новом контакте и сохранение ответа в чат.
- В модель сессии добавлен селектор полного набора параметров подключения.
- Панель «Чаты» подключает форму поиска и упорядоченный список чатов.

## Шаги реализации

1. Создан `shared/api/request.ts` — единая точка отправки HTTP-запросов с настройкой метода, заголовков и JSON-тела.
2. Создан `features/contact-search/api/checkAccount.ts` — сборка URL из `apiUrl`, `idInstance`, `apiTokenInstance` и отправка POST-запроса.
3. Добавлен селектор полного состояния сессии, чтобы feature получала параметры подключения через публичный API entity.
4. Существующее поле панели «Чаты» перенесено в `ContactSearchForm`; widget теперь только размещает feature.
5. Добавлен селектор кода страны с вариантами `+7` и `+375`; исходное значение — `+7`.
6. Для национальной части разрешены только цифры: 10 для `+7` и 9 для `+375`. Кнопка появляется при непустом вводе и активируется только для валидного значения.
7. При вставке проверяется всё значение из буфера. Полные номера с `7`, `+7`, `375` или `+375` разбираются на код и национальную часть; код `375` переключает селектор на `+375`.
8. При submit код и национальная часть объединяются без знака `+`, после чего полный номер передаётся в `checkAccount`.
9. Ответ проверяется по HTTP-статусу и контракту `exist: true` с числовым `chatId`; остальные результаты приводят к сообщению об ошибке над полем.
10. Валидный `chatId` добавляется в объект чатов с очередным `order`; список выводится под формой.
11. Для нового чата один раз запрашивается информация о контакте; успешный ответ сохраняется в `contactInfo`.
12. Представление чата выбирает имя из `name`, `contactName`, `phoneNumber` и `chatId` в заданном порядке.
13. Представление использует ссылку `avatar`, а при её отсутствии вычисляет одну или две буквы из выбранного имени.

## Состояние, маршруты и зависимости

Маршруты и зависимости проекта не изменялись. В Redux store добавлено состояние `chats` в виде объекта, индексированного по `chatId`; каждая запись может содержать полный ответ `contactInfo`. Номер телефона и сообщение об ошибке хранятся только в локальном состоянии формы. Общий обработчик использует встроенный `fetch`.

## Ограничения

- Вставляемые номера с пробелами, скобками и дефисами не нормализуются и считаются невалидными.
- Во время запроса кнопка отправки блокируется без отдельного индикатора загрузки.
- При ошибке получения информации чат остаётся с именем `chatId`; автоматического повтора нет.
