# Предупреждение на странице авторизации

## Цель и границы

Добавить под кнопкой входа информационный блок, который сообщает о тестовом характере проекта, локальном хранении данных авторизации и их передаче только в GREEN-API. Логику авторизации и хранения сессии не менять.

## Наблюдаемое и ожидаемое поведение

Сейчас форма завершается кнопкой «Войти» и не объясняет, где хранятся введённые данные. После изменения под кнопкой отображается красное предупреждение с иконкой восклицательного знака и согласованным пользователем текстом.

## Текущая реализация

- [`LoginForm`](../../src/features/login/ui/LoginForm.tsx) содержит поля и кнопку входа.
- [`sessionPersistence`](../../src/app/store/sessionPersistence.ts) сохраняет валидную сессию в `localStorage` под ключом `maxSender.session`.
- Запросы к API используют параметры сессии; backend в проекте отсутствует.

## Решение

Добавить статический семантический блок `role="note"` непосредственно после кнопки. Использовать встроенную SVG-иконку без новой зависимости и красную цветовую схему Tailwind. Текст вывести дословно в согласованной формулировке.

## Этапы и затрагиваемые файлы

1. Добавить предупреждение в `src/features/login/ui/LoginForm.tsx`.
2. Выполнить сборку, lint, проверку форматирования и Git-проверки.
3. Зафиксировать итог в `status.md` и `implementation.md`.

## Приватность и безопасность

Изменение повышает прозрачность обработки чувствительных данных. Значения `idInstance`, токена и URL не выводятся и не логируются. Механизм хранения и передачи не изменяется.

## Риски и критерии приёмки

Блок расположен под кнопкой, визуально обозначен красным цветом, содержит иконку и точный согласованный текст. Он не влияет на отправку формы и остаётся читаемым на узких экранах.

## План проверки

`npm run build`, `npm run lint`, Prettier для затронутых файлов, `npm run format:check`, `git diff --check`, `git status --short`. Браузерные проверки не выполнять.
