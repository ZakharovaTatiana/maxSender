# Очистка localStorage при выходе

## Цель и границы

При явном выходе пользователя очищать всё содержимое `localStorage` текущего origin. Redux-сессия, вход и восстановление валидной сессии продолжают работать как раньше.

## Наблюдаемое и ожидаемое поведение

Сейчас после `clearCredentials` подписка store вызывает `persistSession` с невалидной сессией, и функция удаляет только ключ `maxSender.session`. После изменения в этой ветке будет вызываться `localStorage.clear()`, поэтому при выходе удалятся все записи текущего origin.

Повреждённая или невалидная запись при старте приложения по-прежнему удаляется точечно через `removeItem`, поскольку это не является явным выходом.

## Текущая реализация

- [`LogoutButton`](../../src/features/logout/ui/LogoutButton.tsx) отправляет `clearCredentials`.
- [`store`](../../src/app/store/index.ts) отслеживает изменение session state и вызывает `persistSession`.
- [`sessionPersistence`](../../src/app/store/sessionPersistence.ts) сохраняет валидную сессию и удаляет ключ приложения для невалидной.

## Решение

В ветке `persistSession` для очищенной сессии заменить `removeItem(SESSION_STORAGE_KEY)` на `clear()`. Эта ветка вызывается подпиской store после logout. Логику чтения и удаления повреждённой записи не менять.

## Этапы и затрагиваемые файлы

1. Обновить очистку в `src/app/store/sessionPersistence.ts`.
2. Выполнить автоматические проверки.
3. Оформить результат в `status.md` и `implementation.md`.

## Приватность и безопасность

Выход удаляет сохранённые параметры подключения и любые другие данные `localStorage` текущего origin. Это необратимая операция для таких данных, но она выполняется только по явному действию пользователя «Выход». Данные других origin недоступны и не затрагиваются.

## Риски и критерии приёмки

После выхода `localStorage.length` для текущего origin равен нулю, Redux-сессия очищена, отображается форма входа. Ошибка или недоступность storage не должны препятствовать выходу из текущей сессии.
