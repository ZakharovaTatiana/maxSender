# Реализация очистки localStorage при выходе

## Итоговое поведение

После нажатия кнопки «Выход» Redux-сессия очищается. Подписка store передаёт новое состояние в `persistSession`, где выполняется `localStorage.clear()`. В результате удаляются все записи `localStorage` текущего origin, после чего отображается форма входа.

При запуске приложения повреждённая или невалидная запись `maxSender.session` по-прежнему удаляется отдельно через `removeItem`; остальные ключи в этом сценарии сохраняются.

## Ключевые изменения

- В ветке невалидной/очищенной сессии `persistSession` используется полная очистка storage.
- Компоненты выхода, Redux-state, маршруты, API и зависимости не изменены.

## Ограничения и технический долг

`localStorage.clear()` удаляет не только сессию MaxSender, но и любые другие ключи текущего origin. Это намеренное поведение по требованию задачи. Если storage недоступен или выбрасывает исключение, выход из Redux-сессии всё равно завершается, но браузерные записи могут сохраниться.

## Проверка

- `npm run build` — успешно.
- `npm run lint` — успешно.
- `npm run format:check` — успешно.
- `git diff --check` — успешно.
- Браузерные smoke checks не выполнялись.

## Поставка и откат

Дополнительные шаги поставки не требуются. Для отката следует заменить `localStorage.clear()` обратно на `removeItem(SESSION_STORAGE_KEY)` в `persistSession`.
