# Сохранение параметров входа

## Цель и границы

Сохранять параметры `idInstance`, `apiTokenInstance` и `apiUrl` в `localStorage` после авторизации, восстанавливать валидную сессию при открытии приложения и удалять сохранённые данные при выходе.

Серверная проверка параметров, шифрование на стороне клиента и синхронизация с другими устройствами в задачу не входят.

## Наблюдаемое и ожидаемое поведение

Сейчас параметры хранятся только в Redux state и теряются после перезагрузки. После изменения валидные параметры должны восстанавливать авторизованное состояние, а невалидные или повреждённые данные должны игнорироваться и удаляться.

## Текущая реализация

- `src/entities/session/model/sessionSlice.ts` — состояние сессии и признак авторизации.
- `src/app/store/index.ts` — создание Redux store.
- `src/features/login/ui/LoginForm.tsx` — ввод и первичная проверка параметров.
- `src/widgets/navigation-sidebar/ui/NavigationSidebar.tsx` — выход через очистку Redux state.

## Решение

- Вынести проверку полного набора параметров в модель сессии и использовать её в форме, селекторе и восстановлении данных.
- При создании Redux store прочитать одну запись сессии из `localStorage` и передать валидные данные как preloaded state.
- Подписаться на изменения store: валидную сессию сохранять, пустую или невалидную удалять.
- Повреждённый JSON и данные неверной структуры удалять без ошибки приложения.

## Этапы и затрагиваемые файлы

1. Добавить общую валидацию параметров сессии.
2. Добавить модуль чтения, записи и удаления сессии из `localStorage`.
3. Подключить восстановление и синхронизацию при создании store.
4. Проверить вход, перезагрузку, выход и невалидные сохранённые данные.

## Приватность и безопасность

`apiTokenInstance` является чувствительным значением и по требованию задачи сохраняется в `localStorage` в открытом виде. Данные доступны JavaScript-коду того же origin и сохраняются между сессиями браузера. В приложении нельзя допускать XSS; при развитии авторизации следует рассмотреть серверную сессию или другое защищённое хранение.

Параметры не должны выводиться в интерфейс, консоль, документацию задачи или сообщения об ошибках.

## Риски

- `localStorage` может быть недоступен или выбрасывать исключения; приложение должно продолжать работать только с Redux state.
- Изменение схемы данных потребует миграции или сброса сохранённой записи.
- Наличие параметров подтверждает локальное состояние авторизации, но не их действительность на сервере.

## Критерии приёмки

- После входа три параметра сохраняются в одной записи `localStorage`.
- После перезагрузки валидные параметры восстанавливаются в Redux state.
- Пустые, повреждённые или невалидные параметры не авторизуют пользователя и удаляются из хранилища.
- После выхода Redux state и запись `localStorage` очищаются.
- При недоступном `localStorage` приложение не падает.

## План проверки

- `npm run build`, `npm run lint`, `npm run format:check`, `git diff --check`.
- Ручной smoke test: вход → проверка наличия записи → перезагрузка → восстановление → выход → отсутствие записи.
- Ручной негативный тест: повреждённый JSON и невалидный URL в сохранённой записи.
