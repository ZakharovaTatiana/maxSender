# Реализация

## Итоговое поведение

После входа `idInstance`, `apiTokenInstance` и `apiUrl` сохраняются одной JSON-записью в `localStorage`. При следующем открытии приложения запись проверяется общей схемой валидации и используется как начальное состояние Redux. Выход очищает Redux state, после чего подписка store удаляет сохранённую запись.

Повреждённые и невалидные данные удаляются. Если браузер запрещает доступ к `localStorage`, приложение продолжает работать с состоянием в памяти текущей вкладки.

## Ключевые изменения

- Добавлена единая проверка параметров: числовой непустой `idInstance`, непустой после trim токен и корректный HTTP/HTTPS `apiUrl`.
- Форма входа и селектор авторизации используют одну функцию валидации.
- Добавлен модуль persistence с ключом `maxSender.session`.
- Валидная сохранённая сессия передаётся в Redux как `preloadedState`.
- Подписка Redux сохраняет изменённую валидную сессию или удаляет запись после очистки.
- Ошибки чтения, JSON parsing, записи и удаления перехватываются без вывода значений параметров.

## Ограничения и технический долг

- Токен хранится в `localStorage` в открытом виде и доступен JavaScript-коду того же origin.
- Параметры проверяются только структурно и не подтверждаются запросом к API.
- Версионирование и миграция формата сохранённой сессии пока отсутствуют; несовместимые данные будут удалены.

## Проверка

- `npm run build` — успешно.
- `npm run lint` — успешно.
- `npm run format:check` — успешно.
- `git diff --check` — успешно.
- Smoke test «вход → перезагрузка → восстановление → выход → перезагрузка» — успешно.
- Обработка повреждённого JSON и недоступного хранилища подтверждена защитными ветками реализации; значения параметров в вывод не попадали.

## Поставка и откат

Дополнительная миграция не требуется. При поставке новая версия автоматически удалит невалидную запись `maxSender.session`. Для отката к версии без persistence рекомендуется удалить этот ключ из `localStorage`.
