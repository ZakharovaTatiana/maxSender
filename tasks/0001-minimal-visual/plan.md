# Минимальный визуал

## Цель и границы

Реализовать минимальные состояния главной страницы. Неавторизованному пользователю показывается форма с полями `idInstance`, `apiTokenInstance` и `apiUrl`, переключателем видимости токена и кнопкой входа. Авторизованному пользователю показываются левая панель управления и заготовка списка чатов.

Подключение к API не входит в текущую задачу. В рамках текущей реализации пользователь считается авторизованным, когда все три параметра сохранены в Redux state и не пусты.

## Наблюдаемое и ожидаемое поведение

До реализации главная страница содержала только текст-заглушку. Ожидаемый результат — центрированная форма входа и минимальная авторизованная оболочка, визуально основанные на сайте-примере и адаптированные для мобильных и десктопных экранов.

## Текущая реализация

- `src/pages/main/ui/MainPage.tsx` — текущая главная страница.
- `src/app/store/index.ts` — корневое Redux-хранилище.
- `src/app/styles/index.css` — глобальные стили.

## Решение

- Добавить в состояние сессии поля `idInstance`, `apiTokenInstance` и `apiUrl` с исходными пустыми значениями.
- Вынести форму входа в слой `features`.
- На главной странице показывать форму, когда пользователь не авторизован.
- Разрешить в `idInstance` только цифры с очисткой значения при вводе.
- Сделать `apiTokenInstance` полем типа `password` с доступной кнопкой переключения видимости.
- Предзаполнить `apiUrl` значением `https://3100.api.green-api.com` и проверять, что введён непустой HTTP/HTTPS URL.
- При отправке формы сохранить три значения в Redux state.
- Вычислять признак авторизации по наличию трёх непустых значений в state.
- Для авторизованного состояния создать узкую боковую панель и панель чатов по предоставленному скриншоту.
- В боковой панели пока не размещать кнопки управления, кроме выхода.
- Внизу навигации разместить кнопку выхода, очищающую данные сессии.
- В панели чатов оставить заголовок и поиск с текстом «Найти по номеру телефона».
- Использовать один фоновый узор для авторизованного и неавторизованного состояний.

Визуальную основу интерфейсных элементов брать с сайта [web.max.ru](https://web.max.ru/): ориентироваться на его палитру, типографику, форму элементов, отступы и общий характер интерфейса. Адаптировать решения под задачи MaxSender и существующую архитектуру проекта.

## Этапы и затрагиваемые файлы

1. Добавить модель состояния авторизации и подключить её к Redux store.
2. Создать форму входа и оформить главную страницу.
3. Добавить авторизованную оболочку, панель чатов и выход.
4. Проверить типы, сборку, линтер, форматирование, вход и выход вручную.

## Приватность и безопасность

Параметры подключения записываются в оперативный Redux state по явному требованию задачи. Они не сохраняются в `localStorage`, не выводятся в интерфейс или логи и не отправляются по сети. После перезагрузки страницы состояние очищается. Автозаполнение для токена отключено.

## Риски

- Текущее состояние авторизации подтверждает только наличие параметров и не проверяет их на сервере.
- Redux DevTools при подключении могут отображать токен из state; перед production-сборкой потребуется определить требования к хранению чувствительных данных.
- Финальные тексты и фоновые графические элементы могут быть уточнены отдельно.

## Критерии приёмки

- Неавторизованный пользователь видит центрированную форму на главной странице.
- `idInstance` принимает только цифры.
- `apiTokenInstance` скрыт по умолчанию и отображается по кнопке с иконкой глаза.
- Кнопка входа доступна только после заполнения трёх полей корректными значениями.
- `apiUrl` предзаполнен, обязателен и принимает только корректный HTTP/HTTPS URL.
- После отправки формы три значения находятся в Redux state и пользователь считается авторизованным.
- Авторизованный пользователь видит левую панель только с кнопкой выхода и панель «Чаты» с поиском по номеру телефона.
- Кнопка «Выход» очищает state и возвращает форму входа.
- Фон рабочей области совпадает с фоном страницы авторизации.
- Интерфейс адаптивен и доступен с клавиатуры.
