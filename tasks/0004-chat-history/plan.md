# История чата

## Цель и границы

Реализовать первоначальный интерфейс выбранного чата и получение последних сообщений через API с параметрами текущей сессии.

В задачу входят выбор чата из существующего списка, отображение базовой области переписки, первоначальная форма сообщения, загрузка последних сообщений и представление основных данных сообщения. Реальная отправка сообщений, вложения, пагинация старых сообщений, обновление в реальном времени, поиск и редактирование сообщений пока не входят в границы задачи.

## Наблюдаемое и ожидаемое поведение

Сейчас найденные чаты отображаются в панели «Чаты», но выбрать чат и открыть переписку нельзя. После реализации пользователь должен выбрать чат, увидеть его заголовок, форму сообщения и последние сообщения либо понятное состояние загрузки, пустой истории или ошибки.

## Текущая реализация

- `src/entities/chat` — Redux-состояние найденных чатов и их отображение.
- `src/features/contact-search` — добавление чата по номеру телефона и загрузка информации о контакте.
- `src/widgets/chat-panel/ui/ChatPanel.tsx` — список чатов.
- `src/pages/main/ui/MainPage.tsx` — компоновка основной страницы после авторизации.
- `src/entities/session` — параметры подключения к API.
- `src/shared/api` — общий HTTP-транспорт.

## Предварительное решение

- Добавить состояние выбранного чата.
- Показывать одновременно не более одного активного чата и переключать активность при выборе другого.
- При первом открытии чата один раз выполнять `GetChatHistory`, передавая только `chatId` и сохраняя стандартный лимит API в 100 сообщений.
- Хранить историю раздельно по `chatId`, чтобы сообщения разных чатов не смешивались.
- Поскольку метод истории не поддерживает фильтр по типу, до сохранения ответа оставлять только `textMessage` и `extendedTextMessage`, а в объектах — только общие и текстовые поля.
- Разделить состояния первичной загрузки, успешного ответа, пустой истории и ошибки.
- Добавить область переписки рядом с панелью чатов и базовое представление входящих и исходящих сообщений.
- Использовать в области переписки общий фон приложения, сохранив отдельную поверхность заголовка и разместив поле сообщения прямо поверх общего фона.
- Добавить внизу адаптивное текстовое поле с временной отправкой текста в консоль по `Enter` или кнопке; `Shift+Enter` переносит строку.
- Использовать публичные API FSD-слайсов и сохранить направление импортов между слоями.
- Сортировать сообщения от старых к новым, разделять входящие и исходящие по сторонам и группировать историю по локальной календарной дате.

## Согласованный контракт

- Метод: `POST {{apiUrl}}/waInstance{{idInstance}}/getChatHistory/{{apiTokenInstance}}`.
- Тело запроса: только `chatId`; параметр `count` не передаётся, используется значение по умолчанию 100.
- Поддерживаемые типы: `textMessage` и `extendedTextMessage`.
- Первая попытка выполняется при первом открытии чата; повторные открытия не вызывают API независимо от результата первой попытки.
- API возвращает сообщения от новых к старым, поэтому перед сохранением они сортируются по `timestamp` по возрастанию.

## Этапы и затрагиваемые области

1. Уточнить контракт API и критерии отображения сообщений.
2. Спроектировать состояние выбранного чата и истории по `chatId`.
3. Реализовать запрос последних сообщений и обработку состояний запроса.
4. Сделать выбор чата интерактивным.
5. Добавить первоначальный интерфейс заголовка и истории чата.
6. Выполнить релевантные автоматические проверки.

## Приватность и безопасность

История сообщений и сведения об участниках могут содержать персональные данные. Номера телефонов, параметры сессии и URL с токеном нельзя выводить в логи или включать в документацию и тестовые fixtures. На текущем прототипном этапе введённый текст по явному требованию выводится в консоль вместо отправки; это поведение нужно удалить при подключении реальной отправки. Ошибки интерфейса не должны раскрывать данные подключения или сырой ответ API.

## Риски и ограничения

- Медиа, реакции, опросы и другие нетекстовые типы исключаются из состояния приложения.
- Большую историю нельзя загружать или хранить без ограничения количества записей.
- Быстрое переключение между чатами не должно приводить к отображению ответа от ранее выбранного чата.
- До уточнения дизайна интерфейс будет ограничен базовой структурой переписки.

## Критерии приёмки

- Чат можно выбрать из списка.
- Выбранный чат визуально различим и открывается в области переписки.
- Кнопка назад снимает активность с текущего чата, а выбор другого чата переключает активность на него.
- Заголовок открытого чата использует те же имя и аватар, что и список.
- Текстовое поле растёт вместе с содержимым; `Enter` и кнопка отправки выводят непустой текст в консоль и очищают поле.
- Для выбранного чата выполняется запрос последних сообщений по согласованному контракту.
- Запрос выполняется только при первом открытии чата и не передаёт `count`.
- Загрузка, пустая история и ошибка имеют отдельные состояния интерфейса.
- Сообщения разных чатов хранятся и отображаются раздельно.
- В `messages` сохраняются только `textMessage` и `extendedTextMessage` с общими и текстовыми полями.
- Сообщения отображаются от старых к новым; входящие находятся слева, исходящие — справа.
- Сообщения сгруппированы по локальной дате с подписями «сегодня», «вчера» или датой вида «03 сентября 2026 г.».
- В сообщении отображаются текст и время в правом нижнем углу.
- Чувствительные данные не попадают в логи и документацию задачи.
