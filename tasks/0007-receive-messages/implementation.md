# Реализация: приём входящих сообщений

## Поведение и изменения

- При авторизации, в том числе восстановленной, ReceiveNotification запускается только при непустом списке чатов. Добавление первого чата запускает опрос; опустошение списка останавливает его. Изменения сообщений и добавление других чатов не перезапускают цикл. Подключение находится внутри Redux Provider и не зависит от маршрута.
- После каждого завершения получения ставится таймер на 5 секунд. Ошибки, null и пустое тело HTTP-ответа допускаются.
- ReceiptId подтверждается через DeleteNotification. Только `result === true` отменяет таймер и запускает следующее получение сразу. Если получение уже идёт после срабатывания таймера, дополнительный параллельный запрос не создаётся.
- Медленное удаление не задерживает обычный опрос. Повторное удаление одного receiptId не запускается, пока предыдущее находится в работе.
- Body преобразуется в модель сообщения и добавляется в существующий чат независимо от успешности удаления. Повторы отсекаются по idMessage, порядок определяется timestamp.
- При загрузке истории сообщения объединяются с уже имеющимися, чтобы поздний ответ истории не стирал уведомления.
- Выход, смена сессии и размонтирование отменяют запросы и таймер. Поздние ответы не обрабатываются.

## Архитектура

Новая feature `receive-messages` содержит API, цикл опроса и React hook. Компонент `app/providers/NotificationReceiver` подключает её к приложению. Разбор уведомлений добавлен в публичный API сущности chat.

Новые маршруты, поля Redux state, зависимости и настройки не добавлялись. Токены и тела уведомлений не логируются.

## Ограничения

Текущая модель и интерфейс поддерживают `textMessage` и `extendedTextMessage`: входящие и исходящие уведомления. Неизвестные чаты не создаются. Нетекстовые и сервисные уведомления удаляются из очереди, но не добавляются в messages. Настройки уведомлений инстанса автоматически не изменяются.

Задержки таймеров в фоновых вкладках определяются браузером. Отмена HTTP-запроса на клиенте не гарантирует отмену уже выполненного удаления на сервере.

- `git diff --check`.

Проверены отсчёт после ответа, ошибки и пустые ответы, удаление true/false/ошибка, медленное удаление, отсутствие параллельных получений, отмена и поздние ответы, body без receiptId, преобразование текстовых уведомлений, неизвестные чаты, дедупликация и гонка загрузки истории.

Браузерные проверки и реальные запросы к API не выполнялись. Задача принята пользователем 2026-09-26, включая условие запуска только при непустом списке чатов.

## Поставка и откат

Обычная локальная production-сборка. Для отката убрать подключение NotificationReceiver, новую feature и разбор уведомлений; вернуть прежнее присваивание истории в setChatMessages. Миграций данных нет.
