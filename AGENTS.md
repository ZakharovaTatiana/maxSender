# AGENTS.md

## Проект

MaxSender — только фронтенд. Backend, БД и контейнеров в проекте нет; разработка и проверки выполняются локально через npm.

Стек: React 19, TypeScript, Vite 7, Redux Toolkit, React Router 6, Tailwind CSS 4, ESLint и Prettier. Требуется Node.js 22.12+.

## Структура

Используй FSD: `src/app` → `src/pages` → `src/widgets` → `src/features` → `src/entities` → `src/shared`.

- Импорты направлены от верхних слоёв к нижним; слайсы одного слоя не импортируют друг друга.
- Импортируй слайсы через публичный API (`index.ts`).
- Алиасы слоёв настроены в TypeScript и Vite; поддерживай их согласованность.
- Провайдеры, маршрутизация, Redux store и глобальные стили находятся в `src/app`.
- Пока реализованы только главная `/` и страница 404 для неизвестных адресов.

## Команды и проверки

- `npm ci` — установка зависимостей.
- `npm run dev` — локальный запуск Vite.
- `npm run build` — проверка типов и production-сборка.
- `npm run lint` — ESLint.
- `npm run format:check` — проверка Prettier.
- `npm run format` — форматирование всего проекта; для отдельной задачи форматируй только затронутые файлы.

Перед работой выполняй `git status --short`. Сохраняй незавершённые изменения пользователя и ограничивай изменения текущей задачей. После изменений приложения выполняй релевантные проверки и smoke test затронутых маршрутов. Перед завершением выполняй `git diff --check` и `git status --short`. Не добавляй в Git секреты, `.env`, `node_modules` и `dist`.

## Коммиты

Сообщения коммитов пиши на английском языке. Делай их максимально краткими: ограничивайся короткими формулировками по ключевым изменениям, без лишних пояснений.

## Рабочие задачи

Каждую отдельную задачу, затрагивающую логику работы приложения, веди в `tasks/` по правилам [`tasks/README.md`](tasks/README.md). До реализации создай `plan.md`, в процессе обновляй `status.md`, после завершения или принятия реализации добавь `implementation.md`.

Организационные изменения, которые не меняют поведение приложения, в `tasks/` не оформляй.

В `AGENTS.md` держи только устойчивые знания о проекте. Детали конкретной реализации, результаты экспериментов и чек-лист приёмки остаются в каталоге соответствующей задачи.
